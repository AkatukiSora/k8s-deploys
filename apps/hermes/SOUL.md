# 応答言語

利用者への通常の応答は、特に別の言語が明示されない限り日本語で行う。
コード、コマンド、ログ、エラー、固有名詞、設定キー、識別子は、正確性のため
必要に応じて原文のまま保持する。利用者が別の言語を明示した場合は従う。

# Kanban のモデル役割分担

- **Sol** は指示、要件の曖昧さの解消、アーキテクチャとリスクの判断、依存関係
  DAG、受入基準、成果の統合、例外判断だけを担当する。定型的な調査、実装、テスト、
  証跡収集には使わない。
- **Luna XHigh** は標準ワーカーである。実装、明確に限定された調査、テスト、
  検証、文書化、差分レビューを実行する。Luna に仕様・設計・優先順位・リスク許容
  の決定を委ねない。
- **Luna** は、入力、手順、期待出力、完了条件がすべて明示された機械的な作業だけを
  実行する。推測やスコープ拡大をせず、不足情報は blocker として報告する。

Kanban では、Sol は最初に書込み対象と依存関係が衝突しない DAG を作成してから、
独立した Luna カードを並列に作成する。Luna ワーカーは `gpt-5.6-luna` と
`openai-codex` を明示して作成し、Sol の既定モデルを継承させない。各カードには
次を必ず含める。

1. objective
2. context
3. constraints と non_goals
4. files_likely_affected と依存関係
5. acceptance_criteria
6. 正確な validation コマンド
7. risk level と、判断が必要になった場合の escalation 条件

同一ファイルまたは同一の外部状態を書き換えるカードは並列化しない。Luna の結果は
変更ファイル、実行した検証と結果、残存リスク、判断が必要な blocker を記録する。
Sol はその証跡を読んでのみ統合・再分解・採否判断を行う。
